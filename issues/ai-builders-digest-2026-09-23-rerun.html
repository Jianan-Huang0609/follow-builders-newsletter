今天的 feed 里，最值得注意的不是又多了几个 agent，而是 agent 正在改变我们使用软件、完成交易和组织工作的方式：界面退到后台，数据、权限和工作流反而变得更重要。与此同时，真正好用的 agent 仍然依赖克制的产品设计，而不是把更多 token 和更多功能一股脑塞给用户。

替你完成交易的 personal agent，其商业化潜力相当大。想象一下，如果 agent 能端到端处理任意复杂的任务，那么最终，大量商业活动不可避免地会通过它们完成。你会先把日常简单又烦人的任务丢给 agent，等习惯之后，再把更复杂的事情交给它，最终经由这些系统的消费可能比以前更多。降低商业和服务的摩擦，反而会带来更多消费。这既给 agent 提供商带来机会，也给 agent 要交互的商业、本地服务和 B2B 服务层带来全新机会。多个层都能受益。

English

Box CEO Aaron Levie argues that personal agents could increase commerce rather than merely reduce it. People will first delegate small, annoying tasks, then gradually trust agents with more complex purchases and services, creating room for both agent providers and the commerce infrastructure those agents need to use.

The monetization potential of personal agents that are transacting on your behalf you is quite significant. If you imagine agents that are perfectly capable of handling an arbitrarily complex task end to end, then eventually a substantial amount of commerce inevitably goes through them. You’ll start by slinging your daily simple and annoying tasks at the agent. Then as people get used to it, they’ll just start to throw more complex tasks at the agent, ultimately leading to even more spend through these systems than what they were doing before. If you can bring down the friction for commerce and services, then you end up spending even more. This thus creates a ton of opportunity for the agent providers (Muse, etc.), but also completely new opportunities to build the layer that the agents want to interact with (commerce, local, b2b services, etc.). Win/win for multiple layers.

Theme 02

The Missing Layer Is Infrastructure / 被低估的是基础设施

界面可以淡出，但数据、权限、业务逻辑和安全护栏会成为 agent 时代的核心底座。

中文

Aaron Levie 预测，agent 对软件的使用强度可能是人的 100 倍。于是 CRM、ERP、数据平台、安全层、guardrail 和 workflow orchestration 不会变得不重要，反而更关键，因为 agent 可能执行破坏性操作，而它拿到的上下文质量会直接决定工作流成败。

AI agent 对软件的使用量会是人类曾经的 100 倍。即使界面逐渐退到后台，agent 仍然需要人类使用过的许多核心原语。事实上，当 agent 能在系统里执行破坏性操作，或者它访问的上下文决定工作流成败时，这些核心原语在很多方面会变得更重要。CRM、ERP，以及结构化或非结构化数据平台都会如此。现在，能为 agent 提供安全层和护栏、管理人和 agent 的数据、编排工作流业务逻辑的平台，都有巨大机会。新创业公司和能快速转型的既有平台都一样。

English

Aaron Levie predicts that agents will use software far more intensely than people do. That makes CRM, ERP, data platforms, security layers, guardrails and workflow orchestration more important, not less, because an agent can take destructive actions and depends on the quality of the context it receives.

AI agents will use software 100X more than people ever did. Even as interfaces begin to fade into the background as you primarily interact with agents, those agents still need many of the core primitives that people have used. In fact, in many ways these core primitives become even more important when agents can take destructive actions in our systems or where the context they’re accessing with make or break the workflow. This will be true of where you house your CRM or ERP or structured or unstructured data platforms. The platforms that can best act as the security layer and guardrails for agents, manage the data for agents and people, and orchestrate the business logic for workflows have a huge opportunity right now. This is true for brand new startups as well as existing platforms that can move fast enough.

Good Agents Need Restraint / 好 agent 需要克制

工具越强，越不能把复杂度全甩给用户；真正的产品力来自筛选、上下文和清晰的执行路径。

中文

Nikunj Kothari 反对 tokenmaxxing：少数例外之外，那些大肆宣传 token 用量的公司，往往产品体验最差。这个判断提醒我们，agent 产品的关键仍是筛选和持续打磨，而不是把所有工具都扔给模型，期待它自己搞定一切。

除了一些例外，那些吹嘘 tokenmaxxing 的公司，产品体验往往最差。因为好的产品讲究筛选和持续打磨，而不是把所有东西都扔给 agent，指望它自己想办法。‘少即是多’从未如此贴切。

English

Nikunj Kothari pushes back on tokenmaxxing: companies that brag about using more tokens often ship worse product experiences. His point is a useful antidote to capability theater: good agent products still need curation and gardening, not a kitchen sink thrown at the model.

With a few exceptions, the companies boasting about tokenmaxxing have the worst product experiences.. It’s because good products are all about curation &amp; gardening and not throwing the kitchen sink at agents expecting them to figure it out. Less is more has never more apt.
