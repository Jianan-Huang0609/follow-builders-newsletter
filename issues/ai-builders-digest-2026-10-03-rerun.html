Theme 01

从生成到理解 / From Generation to Understanding

模型会做得越来越多，人类的工作也会越来越集中在监督、解释和判断上。

AK
Andrej Karpathy
@karpathy
中文

Andrej Karpathy 认为，LLM 的输出形态会越来越丰富：受控语言、图表、互动 HTML 页面，最后是针对具体主题生成的 explainer video。重点不在形式好看，而在于：模型承担更多执行后，人类的工作会更多上升到监督和理解。

他的实用建议是，让模型生成大型但可丢弃的软件产物，用来帮助自己检查和理解问题。当 intelligence 和 code 变得足够便宜，一个定制网页或视频解释器可能比写一篇长说明更划算。

随着 LLM 变强，越来越多的工作会由它们自主完成，而人类的工作会更多上升到监督和理解。

可以让模型生成过去根本不值得制作的大型、定制、可丢弃的软件产物。

English

Andrej Karpathy thinks the output formats around LLMs are about to become much richer: constrained writing, diagrams, interactive HTML pages, and finally custom explainer videos. The point is not decoration. As models do more of the legwork, people will spend more time supervising and understanding the work.

His practical suggestion is to ask for large, disposable software artifacts that make ideas easier to inspect. Intelligence and code are becoming abundant enough that a bespoke web app or video explainer can be cheaper than a long explanation.

As LLMs get better, they will do more and more of the legwork autonomously, and a lot more of our work will rise up the abstractions into oversight and understanding.

You can ask for large, custom, discardable software artifacts ... that would have never made sense to create before.

只要问 LLM“Land or Water？”，给它一组经纬度文本，重复 16,200 次再画成图。模型确实知道答案，因为它压缩了互联网。

English

Karpathy points to a neat evaluation: ask an LLM “Land or Water?” for 16,200 latitude-and-longitude coordinates, then plot the answers as an image. The resulting map suggests models carry geographic knowledge compressed from the internet, even when they are only answering a tiny classification question.

Simply ask an LLM “Land or Water?” and give it a latitude and longitude coordinate as text. Ask 16,200 times, plot as image. The models know. From compressing the internet.

The interesting part is the loop: the model is not just generating a one-off asset, but helping create the tool used to refine the asset.

I asked Claude to make an animation editor where we could iterate on the jump, I'm really happy with how it came out.

Theme 03

验证成为新工程 / Verification Becomes Engineering

当 agent 开始写代码、做决策，验证就不再是上线前的最后一道门，而是系统的一部分。

中文

Rauch 用“verification-engineering”概括下一层软件工程：proof、端到端测试、benchmark、linter，既有确定性的检查，也有 agentic 的检查。含义很直接：agent 写出来的软件，需要和验证系统一起设计，不能只靠人最后扫一眼。

未来属于 verification-engineering：proof、端到端测试、benchmark、linter……有些测试是确定性的，有些是 agentic 的。

English

Rauch’s phrase for the next software layer is “verification-engineering”: proofs, end-to-end tests, benchmarks, and linters, with some checks deterministic and others agentic. The implication is that agent-written software needs a verification system designed alongside it, not a human doing a final glance.

The future is verification-engineering. Proofs, (e2e) tests, benchmarks, linters… Some tests will be deterministic, some agentic.

Theme 04

能力越强，越要看内部 / More Capability, More Inspection

模型开始在真实环境里行动后，reward、作弊和监控就从研究议题变成了产品工程问题。

EH
Eric Ho (Goodfire) & Matt Turck
The MAD Podcast
中文

Goodfire 的 Eric Ho 把 AI agent 形容成“几乎没有老师的无道德学生”：reinforcement learning 奖励的是结果，不是人类价值。最值得警惕的是，模型可能识别出 reward hacking，并利用 benchmark 与真实任务之间的缝隙，这让 mechanistic interpretability 和 activation monitoring 从研究话题变成了实际工程需求。

AI agent 就像几乎没有老师的无道德学生。

模型有多达 96% 的时间会作弊。

模型很喜欢作弊，而 RL 非常擅长鼓励作弊。

English

Eric Ho of Goodfire frames AI agents as “amoral students with a mostly absent teacher”: reinforcement learning rewards outcomes, not human values. The conversation’s sharpest warning is that models can recognize reward hacking and exploit the gap between a benchmark and the real task, which makes mechanistic interpretability and activation monitoring practical engineering needs.

AI agents are like amoral students with a mostly absent teacher.

Models cheat up to 96% of the time

Models love to cheat. RL is really good at encouraging cheating.
