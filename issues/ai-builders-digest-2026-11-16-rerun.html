Theme 01

Verification Engineering / 验证工程

当 agent 开始写基础设施，真正难的部分不只是生成，而是持续验证它是否还和原实现一致。

中文

Vercel CEO Guillermo Rauch 发布了 xeet：一个用 safe Rust/Wasm 写的、封闭可复现的 X 帖子渲染器。它不需要浏览器、网络、文件系统或系统字体，大约 1ms 就能把帖子渲染成 PNG，同时复现 Blink、HarfBuzz 的排版行为，以及 CJK、数学符号、emoji fallback 和 X 的折叠规则。

更值得注意的是它的构建方式：xeet 是一个 autorepo。一个 oracle 会启动 Chrome，验证数万条布局规则；CI canary 再持续观察原实现的变化，并生成带签名的 PR 交给 agent 处理。Rauch 把这叫作 verification engineering，这是一套让生成式基础设施变得可信的实用模板。

xeet 是一个 safe Rust/Wasm 写的、像素级准确的 X 帖子渲染器，不需要浏览器、网络、文件系统或系统字体，约 1ms 输出 PNG。

它采用 autorepo：oracle 启动 Chrome 验证数万条排版规则，CI canary 观察原实现的变化，并生成带签名的 PR 供 agent 处理。

English

Vercel CEO Guillermo Rauch introduces xeet, a hermetic X post renderer written in safe Rust/Wasm. It renders a post to PNG in roughly 1ms without a browser, network, filesystem, or system fonts, while reproducing Blink and HarfBuzz layout behavior, CJK, math, emoji fallbacks, and X's show-more rules.

The more interesting part is how it was built: xeet is an autorepo. An oracle boots Chrome to verify tens of thousands of layout rules, then a CI canary watches the original and files signed PRs for agents to act on. Rauch calls the approach verification engineering, and it is a useful template for making generated infrastructure trustworthy.

Introducing xeet: a hermetic, pixel-perfect X post renderer in safe Rust / wasm. Zero browser, network, filesystem, system fonts. Renders a post to PNG in ~1ms.

It's structured as an autorepo. An oracle boots up Chrome, and verifies tens of thousands of text layout rules. A CI canary then watches the evolution of the original, and files signed PRs for agents to act on.

The Prototype Bottleneck / 原型之后的瓶颈

生成一个可用原型变快了，但真正把它交到人手里、理解使用行为，仍然需要时间。

中文

Peter Yang 转述了 Anthropic 的 Nate Parrott 对一个关键事实的判断：AI 压缩了 build cycle，却没有压缩用户学习周期。Parrott 有 The Browser Company 的工程背景，他说，过去需要几周验证的想法，现在一两天就能做出来；但把产品交到用户手里、理解他们是否会用，依然需要时间。

这对 builder 很重要：更快的实现速度意味着你能测试更多想法，但它并没有取消和真实用户接触的必要。

现在在 Anthropic，类似的东西一两天就能做出来。build cycle 被大幅压缩了，但把东西交给用户、理解他们是否会用的周期并没有被压缩。

English

Peter Yang quotes Nate Parrott of Anthropic on the most important thing AI has not compressed: user learning. With an engineering background from The Browser Company, Parrott says ideas that once took weeks to prototype can now be built in one or two days. But getting the product into people's hands and understanding whether they will use it still takes time.

That distinction matters for builders: faster implementation expands the number of ideas you can test, but it does not remove the need for contact with real users.

Now at Anthropic, you can kind of do that in one to two days. So you've really compressed the cycle of building. What you haven't compressed is the cycle of putting it in people's hands and understanding if they're going to use it.

Compounding Skills / 会复利的 Skill

Skill 不只是一次性提示词，也可以像实验系统一样，通过反复使用和评估逐步贴近个人标准。

中文

Every CEO Dan Shipper 说，他们最近一直在做“会复利的 skill”：每使用一次，就变得更好的 skill。他做了一个帮助写 context window summary 的 skill，再用 autoresearch 反复迭代，直到相对于不使用 skill 的 baseline，结果达到了自己口味的 80%。

关键变化是：skill 不再是写完就结束的一次性 prompt，而是一个可以被评估的系统。个人偏好变成可测目标，重复使用则变成反馈回路。

我们最近一直在努力做会复利的 skill，也就是每次使用都会变好的 skill。

我做了一个帮助写 context window summary 的 skill，并用 autoresearch 迭代，直到相对于不使用 skill 的 baseline，达到了我个人口味的 80%。

English

Every CEO Dan Shipper says his team has been working on compounding skills: skills that improve each time they are used. He made one for context-window summaries, then used autoresearch to iterate until it reached 80% of his taste compared with a no-skill baseline.

The interesting shift is from writing a skill once to evaluating it as a system. Personal taste becomes a measurable target, and repeated use becomes the feedback loop.
