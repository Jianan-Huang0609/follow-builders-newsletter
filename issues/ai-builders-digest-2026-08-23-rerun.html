Evals: AI's New Bottleneck / Eval：AI 落地的新瓶颈

两个来自不同角度的人指向同一个结论：没有好的评估，自动化就无从谈起。

中文

Box CEO Aaron Levie 点中了 AI 落地里最被低估的瓶颈：eval。他的核心判断是——AI 的扩散速度，受「有没有好的 eval」的限制，远超大多数人意识到的程度。

每次模型发布时大家看到的那些 eval 很有用，但它们只告诉你通用进展和模型的相对水平。真正的大机会在别处：针对企业实际跑的那些工作流的 eval，细化到具体某一家公司的场景。

他收尾那句很锋利：「你没法自动化一个连进展都无法评估的东西。」企业不能只凭感觉（vibes）就把活交给 agent，得有真实的度量。

AI 的扩散受限于好的 eval，远超大多数人意识。每次模型发布那些 eval 很有用，但只告诉你通用进展和模型的相对水平。

更大的空间是企业工作流的 eval，细化到具体公司。

这会是巨大的空间，因为你没法自动化一个连进展都无法评估的东西。企业不能只靠感觉。

English

Box CEO Aaron Levie lands on the most underrated bottleneck in AI adoption: evals. His argument—AI diffusion is far more rate-limited by having good evals than most people realize.

The evals we see with every model release are useful, but they only show general progress and relative capability. The bigger opportunity over time is evals on all the major workflows enterprises actually run, down to the specifics of a single company.

His punchline: 'You can't automate what you can't assess the progress on.' Enterprises won't be able to run on vibes—they'll need real measurement before they can hand work to agents.

AI diffusion is far more rate limited by having good evals than most realize. The kind of evals that you see for every model release are incredibly helpful, but only tell you the shape of general AI progress and the relative capability level of models.

The far bigger space over time are evals on all the major workflows that enterprises do, down to the specifics of an individual company.

This will be a huge space over time because you can't automate what you can't assess the progress on. Enterprises will not be able to go just on vibes.

核心观点：eval 上的 hill climbing（爬山），说白了就是「挑一个重要的维度，然后往死里优化它」——可以是某个功能的质量、向相邻场景扩展，或者降成本、降延迟。

The Agent-Native Web Takes Shape / Agent 原生互联网成形中

从 Kevin Scott 的愿景到 Codex 的用量排查，agent 生态正在补上最不性感但最关键的地基。

KS
Kevin Scott
Microsoft CTO · AI & I by Every
中文

一句话 takeaways：微软 CTO Kevin Scott 今年真正的主线不是更大的模型，而是「agentic web」——建一个 agent 能真正替你动手的生态，让 MCP 这样的开放协议扮演当年 HTTP 之于互联网的角色。

他点名了一个大多数人还没意识到的问题：capability overhang（能力过剩）。模型的推理能力已经跑在了产品实际交付的前面，整个行业都得想办法把这个缺口补上。

要让 agent 真正有用，有两件事必须先解决：更好的记忆（今天的 agent 是「事务性的」，每次会话都从零开始），以及一套真正的安全模型。他的主张是：agent 需要身份和权限系统，能主动问一句「我想做这件事，需要哪些权限？」

他对 coding 未来的态度也难得地不教条：他现在还在用 vi 写代码，后悔当初拖了太久才学 3D 打印，给的建议就一句「保持好奇，多试试——好用就用，不好用就算了」。没有「一个 agent 一统天下」这回事。

如果 agent 要有用，它们必须能替你采取行动……你需要一个很像互联网的生态。

MCP 这种简单开放的协议，在 agentic web 里扮演的角色，就像 HTTP 之于互联网。

我最近一直在谈这个叫 capability overhang 的东西。

我们需要 agent 有身份，这样才能建权限系统。

保持好奇，多试试，好用就用，不好用就算了。

English

The takeaway: Microsoft CTO Kevin Scott's big story this year isn't bigger models—it's the 'agentic web': building an ecosystem where agents can actually take action on your behalf, with open protocols like MCP playing the role HTTP played for the internet.

Scott names a problem most people haven't: the 'capability overhang.' Model reasoning has gotten ahead of what we actually ship in products, and the whole industry has work to do closing that gap.

Two things have to get sorted out for agents to be useful: better memory (today's agents are 'transactional'—you start from scratch every session), and a real security model. His pitch: agents need identities and entitlement systems so they can ask, 'I want to do this, what permission do I need?'

He's also refreshingly non-dogmatic about the future of coding: he still writes code in vi, waited too long to learn 3D printers, and advises 'be curious, try stuff—if it works for you, use it; if it doesn't, don't.' No 'one agent to rule them all.'

if agents are gonna be useful, they have to take action on your behalf... you need an ecosystem that looks a lot like the Internet.

you've seen the first glimmers of real progress with super awesome, simple open protocols like MCP that are serving the same purpose in this agentic web as HTTP does on the internet.

I've been talking a lot lately about this thing called the capability overhang.

we need agents to have identities, so that you can build entitlement systems.

be curious, try stuff, and if it works for you, use it. And if it doesn't, don't.
