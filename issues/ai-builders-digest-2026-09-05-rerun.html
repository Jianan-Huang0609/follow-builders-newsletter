下一层 agent 基础设施不一定是另起一套世界，而可能是让现有网页直接暴露可用的工具和上下文。

中文

Guillermo Rauch 很看好 WebMCP，因为 agent 需要借助已经存在的 Web 基础设施，而不是重新造一个封闭世界。他举的例子比口号更有意思：Next.js 的开发页面可以直接把调试工具暴露给正在测试该页面的 agent，并带上页面级上下文，不必再翻 server logs，也不用额外找和配置 MCP server。浏览器因此同时变成产品界面和调试界面。

非常看好 WebMCP。就像 Tesla FSD 要适应真实世界一样，agent 也需要使用现有的 WWW 基础设施，WebMCP 会让这一点更高效。 一个很特别的例子：Next.js 开发页面可以把调试工具直接暴露给正在测试具体 tab 的 agent，并提供页面级上下文，不必翻 server logs，也不需要单独寻找和配置 MCP server。页面直接暴露自己的 agent tools。 在这个世界里，𝚏𝚡 + 𝚊𝚐𝚎𝚗𝚝-𝚋𝚛𝚘𝚠𝚜𝚎𝚛 会成为完整的 Web 开发栈，而且调试深度没有损失。

English

Guillermo Rauch is bullish on WebMCP because agents need to ride the web infrastructure that already exists. His concrete example is more interesting than the slogan: a Next.js dev page could expose debugging tools directly to the agent in the tab being tested, with page-specific context, instead of forcing developers to search logs and configure a separate MCP server. The browser becomes both the product surface and the debugging interface.

Super bullish on WebMCP. Much like Tesla FSD meets the world where it is (streets, stoplights, potholes and all), agents *need* to ride the existing WWW infrastructure… WebMCP makes it more efficient. Some pretty unique wins too. e.g: Next.js dev pages could expose debugging tools directly to agents in the specific tab they’re testing, with page-specific context, instead of sifting through server logs. No separate MCP server to find and configure because the page directly exposes its own 'agent tools'. e.g: in this world 𝚏𝚡 + 𝚊𝚐𝚎𝚗𝚝-𝚋𝚛𝚘𝚠𝚜𝚎𝚛 is a complete web dev stack with zero loss in debugging depth

Build the Workflow, Then Learn / 先自动化，再理解 AI

关于 AI product building，最可靠的学习路径不是继续读更多方法论，而是拿一条自己熟悉的流程做完整实验。

中文

Madhu Guru 给了一个周末就能做的 AI product building 练习：挑一条自己熟悉的工作或生活流程，把它完整地自动化。这个练习会逼你面对真正的产品问题：端到端体验应该是什么样，MCP 和 tools 放在哪里，人应该保留在哪些环节，以及如何评估结果。做完一次，往往比读一个月方法论学得更多，因为流程里的断点会自己暴露出来。

这个周末可以做一件实用的事来提升 AI 产品构建能力：选一条你熟悉的工作或生活流程，用 AI 把它完整自动化。 这个练习会迫使你思考：1/ 什么是好的端到端体验？2/ 应该如何使用 MCP 和 tools？3/ 人应该留在 loop 的哪里？4/ 如何评估？ 然后继续提高目标。亲手做一次，比读一个月 AI 产品构建内容学得更多。唯一的学习方式就是构建。

English

Madhu Guru offers a weekend exercise for learning AI product building: choose a workflow you know well and automate the whole thing. The exercise forces you to confront the real product questions—what the end-to-end experience should be, where MCPs and tools belong, where humans stay in the loop, and how to evaluate the result. One complete build teaches more than a month of reading because it exposes the seams.

Here’s one practical thing you can do this weekend to get better at building AI products. Pick a workflow you know well - from your personal life or your work. Automate the whole thing with AI. Use the AI product you’re comfortable with - you’ll probably have to experiment with a few. This exercise will force you to think about 1/ What does a great end-to-end experience look like? 2/ How should you use MCPs and tools? 3/ Where should humans stay in the loop? 4/ How do you evaluate it? Then keep expanding the ambition. You’ll learn more by doing this once than by reading about AI product building for a month. The only way to learn is to build.
