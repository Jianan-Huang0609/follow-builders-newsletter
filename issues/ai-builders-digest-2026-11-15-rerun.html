From Models to Workflows / 从模型到工作流

真正的生产力不只来自模型更聪明，还来自它能否可靠地使用软件、处理上下文并嵌入工作流。

中文

Box CEO Aaron Levie 认为，agent 在 coding、tool use、computer use 和数学上的进步速度，会快过其他知识工作领域。结果可能不是只有少数工作被自动化，而是越来越多工作会被重塑成 coding-shaped，因为 agent 能生成软件，也能操作人们已经在用的软件。

他更关键的判断是：模型不需要什么都知道，而是要把软件使用或生成能力，和领域知识、工作流里的判断结合起来。一旦这个组合成立，更多领域都会被打开。

越来越多的工作会变成 coding-shaped，以适应 agent 擅长的事情。

模型真正需要的是有效使用或生成软件的能力，加上领域知识，在工作流里做出正确判断。

English

Box CEO Aaron Levie argues that agents will improve faster in coding, tool use, computer use, and math than in other areas of knowledge work. The result may be that more work gets reshaped into something coding-like, because agents can generate software and operate the tools people already use.

His sharper point is that models do not need to know everything. They need to combine effective software use or generation with deep domain expertise and judgment inside a workflow. Once that combination works, many more domains become accessible.

More and more work just becomes coding-shaped to adapt to what agents are good at.

They really have to know how to use or generate software effectively combined with deep domain expertise to make the right judgment calls inside of workflows.

Interfaces Agents Can Actually Use / Agent 真正能用的界面

当 UI 的行为被做成可复用的能力，agent 不只是生成页面，而是在调用一套成熟的交互积木。

Theme 03

Reliability Before Autonomy / 自主之前先谈可靠

模型能在某些维度超越人类，不代表它已经可以独立承担完整任务。

UL
Unsupervised Learning
Unsupervised Learning Podcast
中文

Jev 创始人 Jogo 的核心判断是：AI 应该服务于 machine-native software，而不是只被当成面向人类消费的字符串生成器。开发者最清楚自己的应用需要什么可靠性，所以模型应该提供足够的控制旋钮，让模型和使用场景一起演化。

他不太相信只看 benchmark，也警惕被某一家模型提供商锁死。一个系统在某个维度超越人类，不代表它能独立完成真实工作，因为 intelligence 不是单一刻度，真实工作还涉及副作用、可回滚性和判断。按他的估计，coding agent 目前平均带来的提升是不错但不巨大的 20%–40%，而且高度依赖场景。

他最后的提醒很直接：builder 要找回主动权，重新思考 software、interface，以及 AI 到底能创造什么。

电脑其实很少真正需要 string，因为它们处理的是 bits。

把 intelligence 当成由当天 benchmark 测出来的单一刻度，是完全错误的。

我的估计是提速 20% 到 40%。

English

Jev creator Jogo's central argument is that AI should be built for machine-native software, not treated as a string generator for human consumption. Developers know the reliability profile their applications need, so models should expose the right knobs and let use cases coevolve with them.

He is skeptical of benchmark worship and model-provider lock-in. Even systems that look superhuman on one axis still need humans in the loop, because intelligence is not a single scale and real work includes side effects, reversibility, and judgment. His practical estimate is that coding agents currently provide a decent but modest average speedup, roughly 20–40% depending on the use case.

The memorable conclusion: builders need to recover their agency and start rethinking software, interfaces, and what AI can be used to create.

I don't think a computer really ever wants a string ... because they operate on bits.

Intelligence as this single axis that is measured by whatever the benchmark of the day is is totally wrong.

My estimates are in the 20 to 40% speed up range.

Builders' New Operating Layer / Builder 的新操作层

从 prompt 审计到自治企业，新的工作方式正在从个人技巧变成可重复的系统。

中文

Peter Yang 分享了两个适用于 Fable 5.2 的 prompt：/doctor prompt-audit 会检查 Claude Code 的 Claude.md、skills 和 commands 并提出修复建议；/claude-api prompt-audit [skill name] 会深度检查某一个 skill。他希望 Claude Code 每次发布新模型时，都能自动提醒用户跑一遍审计。

真正有价值的地方不在于 prompt 很酷，而在于它把 agent 配置当成了需要回归检查的软件：模型升级后，工作流也要重新验收。

/doctor prompt-audit：审计 Claude Code 配置（Claude md、skills、commands）并提出修复建议。

/claude-api prompt-audit [skill name]：深度审计一个 skill。

English

Peter Yang shares two prompts for Fable 5.2: /doctor prompt-audit reviews a Claude Code setup—Claude.md, skills, and commands—and proposes fixes; /claude-api prompt-audit audits one skill in depth. His wish is that Claude Code would suggest running these audits whenever Anthropic releases a new model.

The useful idea is operational rather than flashy: treat your agent setup as software that needs regression checks after every model upgrade.

/doctor prompt-audit: Audits your Claude Code setup (Claude md, skills, commands) and proposes fixes.

/claude-api prompt-audit [skill name]: Audits one skill in depth.
