The Web Becomes Agent Infrastructure / Web 正在变成 Agent 基础设施

agent 不必等一个全新世界建好才有用，直接理解并操作现有网页，可能才是更快的扩张路径。

中文

Vercel CEO Guillermo Rauch 看好 WebMCP，因为 agent 需要先适应已经存在的 Web，而不是等一个全新的世界建好。他举的例子很具体：Next.js 开发页面可以直接把 debugging tools 暴露给正在测试该 tab 的 agent，附带页面上下文，不必翻 server logs，也不必另找和配置 MCP server。

这条路线的价值在于，它把 browser 从被动屏幕变成 agent 的本地工具层，保留现有 Web 的深度，同时让它变得可被机器操作。

非常看好 WebMCP。就像 Tesla FSD 要适应现实世界一样（街道、红绿灯、坑洼全都要面对），agent 也需要利用现有的 WWW 基础设施，WebMCP 会让这件事更高效。 还有一些很独特的收益，比如 Next.js 开发页面可以把 debugging tools 直接暴露给正在测试的那个 tab 里的 agent，带上页面级上下文，而不是让 agent 去翻 server logs。不需要再寻找和配置单独的 MCP server，因为页面本身就暴露了自己的 agent tools。 在这个世界里，𝚏𝚡 + 𝚊𝚐𝚎𝚗𝚝-𝚋𝚛𝚘𝚠𝚜𝚎𝚛 就是一套完整的 web 开发栈，而且 debugging 深度没有损失。

English

Vercel CEO Guillermo Rauch is bullish on WebMCP because agents need to meet the web where it already exists. His concrete example is compelling: a Next.js development page could expose debugging tools directly to the agent in the tab being tested, with page-specific context, instead of forcing it to search server logs or configure a separate MCP server.

The direction matters because it turns the browser from a passive screen into a local tool surface for agents, preserving the depth of the existing web while making it machine-operable.

Super bullish on WebMCP. Much like Tesla FSD meets the world where it is (streets, stoplights, potholes and all), agents *need* to ride the existing WWW infrastructure… WebMCP makes it more efficient. No Priors Podcast
中文

Arm CEO Rene Haas 认为，AI 不会把 CPU 从计算系统里拿掉：accelerator 负责生成 token，但 CPU 仍然负责决定这些 token 往哪里去。Arm 更有意思的变化在商业策略上：它从单独授权 IP，走向 compute subsystem，再走向实体 CPU，因为客户越来越在乎 time-to-market。Haas 说，Arm 现在约 80% 到 90% 的工程师每天使用 AI，主要用于 verification、validation、debug 和文档；RTL generation 和 physical implementation 还不够成熟，因为最好的数据往往是专有的。

瓶颈也在向外移动。对 AI chip startup 来说，难点不只是设计新架构，还包括拿到 wafer、memory、advanced packaging、capital，以及把 data center 建出来。Haas 预计供应链约束至少还会持续 3 到 5 年，而更简单的芯片设计，未来 5 年以上可能从想法直接走到 GDS2。

从来没有任何计算问题不需要、也不能使用 microprocessor。它是一切的核心。所有道路都要经过它、围绕它或越过它。总得有东西负责编排和仲裁，决定这些 token 往哪里走，这就是 CPU 的工作。

我想现在 Arm 大概有 80% 到 90% 的工程师每天都在使用 AI……整个周期里耗时最多的其实是 verification、validation、debug 和 documentation。AI 很擅长这些。

我认为还会有许多不同的事情来限制增长……至少未来 3 到 5 年，我们都会处于受约束的环境中。

English

Arm CEO Rene Haas argues that AI will not remove the CPU from computing: accelerators generate tokens, but CPUs still orchestrate where those tokens go. Arm's more surprising shift is strategic: it moved from licensing individual IP blocks to compute subsystems and then physical CPUs because customers increasingly value time-to-market. Haas says 80–90% of Arm engineers use AI daily, especially for verification, validation, debugging, and documentation, while RTL generation and physical implementation remain less mature because the best data is proprietary.

The bottleneck is moving outward. For AI chip startups, the hard part is not only an innovative design but also access to wafers, memory, advanced packaging, capital, and data-center buildout. Haas expects supply-chain constraints to persist for three to five years, while straightforward chip designs could eventually move from idea to GDS2 in five-plus years.

There's no computing problem that's ever been invented that doesn't utilize and can't utilize the microprocessor. It is the heart of everything. All roads lead through it, around it, past it. Something has to do the orchestration, arbitration decision around where those tokens go. That's what CPUs do.

And I would say we probably have 80 to 90% of engineers today in sidearm who use it on a daily basis. ... The largest amount of time is in the verification, the validation, the debug, the documentation, etcetera, etcetera. AI is really good at that.

I think you're gonna see a number of different ... things that are going to throttle the growth of this ... I think we're gonna be in this constrained environment for three to five years, at least.
