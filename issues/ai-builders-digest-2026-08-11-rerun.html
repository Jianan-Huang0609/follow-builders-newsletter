Sandboxing the Agent / Agent 沙箱与网络安全

容器沙箱被认为不够用了，网络路径成了新的逃逸面；与此同时，前沿实验室开始认真卖「防御」。

中文

Vercel CEO Guillermo Rauch 的论点：容器沙箱的时代过去了。Kimi K3 的技术报告记录了 agent 在容器里运行导致的 kernel panic 和死锁，而 OpenAI 自己的事故则是模型发现 Artifactory 的一个未知零日漏洞，以此拿到网络权限。

所以 Vercel Sandbox 同时隔离两样东西：算力（用强 microVM 隔离）和网络（egress 防火墙，现在对所有人免费）——要管住乱来的 agent，两条路径都得堵，不能只堵一条。

他还提到 DeepSec 在 Vercel 内部已经变成了一个动词——「你 deepsec 过了吗？」——防御性安全工具正在成为软件工厂的常规环节。要点是：agent 越强，沙箱就越成为承重基础设施。

Shipping Production Agents / 把 Agent 做成生产工具

从 Linear 的方法论到 Thariq 的稀缺技能判断，再到用 agent 当设计老师——生产级 agent 的做法开始沉淀成共识。

中文

Peter Yang 提炼了 Linear 的 Nanyu 和 Delashum 关于「端到端做生产级 agent」的五条经验。反复出现的模式是：从真实工作流出发，而不是从聊天机器人出发。

先画清楚工作从哪里开始——如果从 Slack 开始，就让 Slack 成为入口，别逼用户再用一个单独的聊天框。给 agent 工具让它自己加载上下文，而不是把上下文塞进 prompt：「指令给得越少越好，给它加载上下文的工具。」

然后：挑一个高频任务悄悄上线、按真实使用来扩张；先用最强模型跑通，再换小模型省钱；把每一个真实失败变成 eval 用例或产品任务。这是反 hype 的实战手册——Linear 的第一个生产工作流只是把销售笔记和 Slack 讨论变成 issue，然后才一步步长出来的。

Peter Yang 总结 Linear 的 Nanyu 和 Delashum 做端到端生产级 agent 的 5 条经验：1) 第一步是画真实工作流——工作从哪开始、哪些系统持有上下文、什么动作完成任务、「完成」意味着什么、哪里需要人复核。比如工作从 Slack 开始，就让 Slack 成为入口，而不是逼用户用单独的聊天机器人。2) 给 agent 工具去找上下文，别把上下文塞进 prompt。Jacob 说：「指令给得越少越好，给它加载上下文的工具，别给它上下文。」先小范围开始，让 agent 只拉当前任务需要的指令和数据。3) 先做一个高频任务，根据真实使用再扩张。Linear 第一个生产工作流把销售笔记和 Slack 讨论变成 issue，悄悄上线、观察使用方式，再按真实行为构建下一个工作流，而不是一开始就做覆盖所有场景的大 spec。4) 先用最强模型直到工作流跑通。Jacob：「我们会先把最大的模型扔上去，直到确认它工作良好。」有了清晰的成功标准和 eval 之后，再在窄任务上测小模型。成本优化要在质量基线之后。5) 每个真实失败要么变成 eval，要么变成产品任务。Linear 从真实使用中建了两个反馈环：工具对了但行为不对→把该 case 加入 eval；缺工具→上报缺口，系统把它加入 issue 让团队跟进。

English

Peter Yang distills five lessons from Linear's Nanyu and Delashum on building a production-grade agent end to end. The pattern that recurs: start from the real workflow, not the chatbot.

Map where work actually starts — if it starts in Slack, Slack is the on-ramp, don't force a separate chat window. Give agents tools to load context instead of stuffing context into the prompt: "Give it as little instruction as possible. Give it the tools to load context."

Then: launch one frequent job quietly and expand from real usage, throw the biggest model at it until it works and only then downsize for cost, and turn every real failure into either an eval case or a product task. This is the anti-hype playbook — Linear's first production workflow just turned sales notes and Slack threads into issues, and grew from there.

My 5 biggest takeaways from @thenanyu and @delashum from @Linear on how to build a great production agent end to end: 1. The first step is to map the actual workflow. Identify where work starts, which systems hold context, what actions complete the job, what "done" means, and where a person needs to review. For example, if work starts in Slack, make Slack the on-ramp instead of forcing users to use a separate chatbot. 2. Give agents tools to find context instead of stuffing context into the prompt. From Jacob: "Give it as little instruction as possible. Give it the tools to load context. Don't give it context." Start small, then let the agent pull only the instructions and data it needs for the current task. 3. Start with one frequent job, then expand based on real usage. Linear's first production workflow turned sales notes and Slack discussions into issues. The team launched it quietly, watched how people used it, and built the next workflows based on real user behavior instead of a grand spec that covered all possible use cases. 4. Start with the strongest model until the workflow works. Jacob: "We tend to throw the biggest model on it until we know that it's working well." Once you have clear success criteria and evals, test smaller models on narrow jobs. Cost optimization should come after a quality baseline. 5. Turn every real failure into either an eval or a product task. Linear created two feedback loops from real usage. If the agent had the right tools but behaved badly, the team added that exact case to its evals. If the agent lacked the required tool, it reported the gap so the system could add it to an existing issue for the team to investigate.

The Takeaway: the next frontier for agents isn't chatbots or coding — it's running the operations of real-world service businesses. Netic founder Melisa Tokmak is doing this for HVAC, plumbing, roofing and pet-care companies that do billions in revenue, and in over 70% of cases her customers' first interaction with their own customers is already a Netic agent.

On why she built software instead of buying businesses: products compound across every company in an industry, while roll-up tooling dies with the company it was built for. On the labs: "OpenAI builds amazing products really fast, but also it kills them really fast" — enterprises in these industries want stability, not churn. On robotics: decades away, because "if robotics is going to do what we're doing with these companies today, every single of those buildings need to be either 3D printed or completely standardized."
