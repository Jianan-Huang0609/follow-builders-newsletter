The Agentic Web, One Year In / Agent 互联网成形中

Microsoft CTO 说 MCP 之于 agent 就像 HTTP 之于网站；Claude 的会话开始在浏览器、桌面、手机之间漫游；agent 的形态一年内从 CLI 走到了云端服务。

KS
Kevin Scott (Microsoft CTO)
AI & I by Every
中文

一句话总结：下一代的互联网不只是给人用的——它是给 agent 用的，而 MCP 就是它的 HTTP。

Microsoft CTO Kevin Scott，一个写了 41 年代码、至今还在用 vi 的老程序员，认为「agentic web」才是今年的真正故事，取代了 scaling law 的炒作。他的核心论证：agent 要有用，就必须能替你采取行动，所以每个有网站、有 API 的服务都得想清楚怎么把自己接进去，让 agent 能和它「对话」。像 MCP 这样简单开放的标准协议，扮演的正是 HTTP 在互联网里的角色，而 NL web 相当于 HTML 的道德等价物。

他点出行业真正的问题是「capability overhang」：模型的推理能力已经跑到了产品实际交付的前面，弥合这个差距是接下来整个行业的集体功课。说到安全，他认为 MCP 简单到足够连贯，社区完全能收敛出一个正确的安全模型——起点是 agent 的身份和授权体系：agent 代表某个人行事，向系统请求它需要的权限，管理员给 yes 或 no。开放，而不是私有。

被问到 agent 会不会毁掉 coding 的「手艺感」，他很松弛：maker 从来都对工具有强烈的意见——「真木工只用手动工具」到电动工具，再到 CNC。他的建议是：「保持好奇，去试。对你有用就用，没用就别用。」他后悔自己等了好久才学 3D 打印，别重蹈覆辙。

他对一年后的预测：agent 会从同步走向异步。你把「去把这事搞定」丢给它，它花几个小时调用各种系统、反复迭代，最后回来说：「我到这一步了，接下来轮到你。」

agent 要有用，就必须替你采取行动——能使用工具、改系统、查各种信息源。要做到这一点，你需要一个长得像互联网的生态。

MCP 这样的简单开放协议，在 agentic web 里扮演的就是 HTTP 在互联网里的角色；NL web 相当于 HTML。

模型的推理能力已经领先于产品实际交付的东西——这就是 capability overhang。

agent 需要身份，才能建授权体系：这个 agent 代表这个人行事，有权访问这些资源。

保持好奇，去试。对你有用就用，没用就别用。

明年你会看到：把「搞定这事」丢给 agent，它花大量时间调用系统、迭代，然后回来说「我到这一步了，轮到你」。

English

The Takeaway: the next web won't be built just for people—it will be built for agents, and MCP is its HTTP.

Microsoft CTO Kevin Scott, a 41-year programmer who still uses vi, argues that the 'agentic web' is this year's real story, replacing scaling-law hype. His core case: agents are only useful if they can take action across systems, so every service with a website or API needs to figure out how to plumb itself through so agents can talk to it. Simple open protocols like MCP play the same role HTTP played on the internet, and NL web is the moral equivalent of HTML.

He flags 'capability overhang' as the industry's real problem: model reasoning has gotten ahead of what products actually deliver to users, and closing that gap is the collective work ahead. On security, he argues MCP is so coherently simple that the community can converge on the right model—starting with agent identity and entitlements: an agent acts on behalf of a person, requests permission for the systems it needs to touch, and admins get a yes or no. Open, not proprietary.

Asked whether agents kill the craft of coding, he shrugs: makers have always had strong opinions about tools—'real woodworkers only use hand tools,' then power tools, now CNC. His advice: 'Be curious, try stuff, and if it works for you, use it. And if it doesn't, don't.' He regrets waiting forever to learn 3D printers; don't repeat that.

His prediction for a year out: agents go from synchronous to asynchronous. You'll hand off 'go sort this out,' the agent will spend hours calling systems, iterating, and come back with 'here's as far as I got—now it's your turn.'

if agents are gonna be useful, they have to take action on your behalf. They have to be able to use tools and make changes in systems and consult information sources that are diverse and rich. And in order for that to really be great, you need an ecosystem that looks a lot like the Internet.

you've seen the first glimmers of real progress with super awesome, simple open protocols like MCP that are serving the same purpose in this agentic web as HTTP does on the internet and where you have things like NL web that are serving the same moral equivalent purpose as HTML does on the internet.

the reasoning capabilities of the models has actually gotten a little bit ahead of what we're using the models to do in products. So I've been talking a lot lately about this thing called the capability overhang.

we need agents to have identities, so that you can build entitlement systems. So you can say this agent is acting on behalf of this person and they're entitled to see these resources in this system.

be curious, try stuff, and if it works for you, use it. And if it doesn't, don't.

by next year, you're going to see people using these agents to like, 'Hey, go sort this out.' And the agent is going to take a lot of time. It's going to go make a lot of calls out to systems... and then at some non trivial amount of time later, you're going to sort of say, okay, here's as far as I got, now it's your turn.
